# V2.1 验证记录

日期：2026-11-03（Asia/Shanghai）。

## 已执行

环境：Windows、Python 3.10.5、Docker、pgvector/pgvector:pg18。使用独立临时容器 `sqlagent-v21-check`，未对现有 `sql_agent-db-1` 的业务数据做迁移或写入。隔离容器验证后停止并自动删除。

运行 `python -m pytest -q --junitxml=docs/v2.1-test-results.xml`：**58 passed，13.60 秒**。52 项离线测试、6 项真实数据库/协议集成测试全部通过。原始 JUnit 报告见 [v2.1-test-results.xml](v2.1-test-results.xml)。

| 验证范围 | 实际结果 |
|---|---|
| AST 策略 | 拒绝写语句、多语句、写入 CTE、SELECT INTO、未授权表列、系统目录、危险函数、限定函数、自定义类型和行锁；合法 JOIN/CTE/UNION 可执行 |
| 评测判定 | 不再接受“额外行中碰巧含正确数字”；检查重复行、NULL、排序和数值精度；30 条参考 SQL 全部通过真实数据库执行 |
| 只读账号 | 仅授权业务表 SELECT；即使关闭默认只读事务配置仍无法 DELETE |
| SQL 超时与取消 | 实际重查询触发语句超时；取消后连接池可继续查询，服务端没有该账号残留的活跃查询 |
| pgvector 增量索引 | 重复入库不增加数量；内容变更覆盖；来源删除清理；缺失向量自动修复；集合前缀隔离稳定 ID |
| HTTP / WebSocket | 输入校验、图复用、过载、截止时间归还槽位、取消确认、生产异常终止、断连清理 |
| MCP stdio | 真实客户端发现 run_sql；子进程接收显式数据库配置，返回隔离数据集的用户数量 6 |
| 静态与配置 | Ruff `E9,F` 检查通过，Compose 配置校验通过，Git diff 空白检查通过 |

测试中有一条第三方 Starlette/AnyIO `BlockingPortal` 弃用提示，不影响结果。GitHub Actions 工作流已新增，尚未推送运行远端 CI。

## 没有执行、不能声称的结果

- 当前环境没有 `DEEPSEEK_API_KEY`，未调用真实模型，没有测得 Agent 执行正确率、答案忠实度或 Token 改善幅度。
- 向量数据库集成使用确定性假 Embedding 验证存储和检索链路，未验证真实 BGE 语义召回质量。
- 未运行真实 API 并发压测，没有可声称的吞吐/P95 提升比例。
- 30 个场景是项目当前回归集，不代表 Spider、BIRD 等公开基准成绩，也不代表大规模多表效果。

补齐模型密钥后，可按 README 在独立评测数据库运行 `python eval.py --mode all`，再对运行中的 API 执行 `python scripts/benchmark.py`。只有实际报告中测得的数字才适合补充到简历。
