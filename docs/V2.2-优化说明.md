# V2.2 优化说明

本次围绕业务口径、多轮分析和答案溯源推进，同时提供真实模型可运行的对话评测。当前环境没有模型密钥，也没有项目 .env，所以没有填写准确率或性能改善比例。

## 业务口径与澄清

`semantics.py` 维护版本化指标注册表：订单金额、订单数量、用户数量、下单用户数，记录计算表达式、单位、定义和时间字段。现有数据只有 users/orders，不包含支付、退款、订单状态和登录行为；用户问收入、销售额、有效订单或活跃用户时，先确认可支持的口径，不能假设缺失数据存在。

`schemas.py` 将确认结果变成可校验参数：metric_id、period 或 date_range。歧义规则在调用模型和业务数据库之前执行，返回 clarification_required 和待补字段。选择可以分几轮补齐，待澄清状态保存在会话中。

时间统一使用 Asia/Shanghai，区间左闭右开。上个月按自然月、本月和近7天按截至今天的自然日解析；自然语言“2026年2月”也可解析。相对时间首次确认后保存具体边界，后续追问继承该范围，显式更改才重算。查询池也设置同一时区，避免 timestamp 条件在UTC和北京时间月界处出现偏差。

边界：这是针对当前业务的规则式澄清，不能识别所有歧义。指标注册表指导 SQL 生成，但未对任意复杂 SQL 做形式化口径证明。平均、最高、明细类查询不会被强行归类为 SUM。跨话题明确切换可用 new_topic，复杂意图仍需靠评测验证。结构化继承范围是指标与时间；其他筛选和排序依赖最近8轮上下文，长对话应重述完整条件。

## 多轮会话与 Checkpointer

`analysis_service.py` 提供 HTTP、WebSocket 和 CLI 共用的单轮入口。`conversations.py` 用 LangGraph + SQLite Checkpointer 保存已完成分析的文字历史、确认条件和待澄清状态，SQL执行图仍使用每轮全新状态。

这样可以保持两条约束：历史文字能帮助理解追问；新一轮答案必须有本轮工具查询证据。旧 ToolMessage、旧查询行、旧调用预算不会进入新一轮。仅保存最近8轮，每条问题和答案均限制长度，避免上下文无限增长。失败或查询阶段取消不提交新历史。

提交使用新 thread_id 写暂存快照，成功后原子切换会话指针，再删除旧 Checkpoint。失败暂存被清理；进程重启时清理未引用的孤立快照。发布阶段遇到取消，会先完成短发布事务，保证不会留下损坏指针。因此客户端在最终响应丢失时，可能发现已经完成的分析仍保存在历史中；这与查询中途失败不污染历史的规则一致。

会话支持1800秒TTL、最多1000个、主动删除和同会话并发409。身份由服务端 API key 映射得到，不能靠请求中的 user_id 声明身份。未配置映射时是本地单用户模式。跨用户尝试访问或删除会话统一404，HTTP与WS一致。

当前存储采用单进程文件锁，适合单API worker的本地项目；异步请求仍可并发。多worker部署应迁移共享存储和跨进程租约。本次没有加入数据库租户RLS；会话隔离不代表数据行权限隔离。

## 答案溯源与数字一致性

`provenance.py` 从最后一次成功、未截断的工具结果生成结构化答案。来源记录规范化 SQL、查询完成时间、结果哈希和行数；引用定位到结果行列，例如 q1:r0:c0。

最终数值展示由代码从单元格生成，模型自由文本中的数字、增长率等不会进入最终答案。预览最多10行10列，长单元格显示摘要，完整值保留在 data；NULL明确显示为空值，不替换成0。流式工具调用期间也不展示模型未经查询的预判文字。

`citations_valid` 会重建展示文本与引用列表，核对结果哈希，拒绝修改值、删引用或追加无依据的文字。它验证内部一致性，不提供密码学签名；如果整个对象被外部重新伪造，哈希本身不能证明数据来自服务端。

取舍：当前答案更像有依据的数据结果卡，少了模型自由叙述的灵活性。引用能证明答案与SQL结果对应，不能证明SQL问对了问题；错误SQL也可以有一致的结果。执行结果评测仍是必要的一层。queried_at是查询完成时间，不是业务表最后更新时间。

## 评测与实证

保留V2.1的30个结果级查询案例，增加引用一致性字段；新增 `evaluation/conversations.json` 的5段10轮交互和 `eval_conversations.py`。新评测包含澄清后查询、条件继承、排名追问、未支持口径转为可支持口径、无上下文追问等场景。

真实模型评测使用相同固定数据库，分别记录状态、SQL执行结果、引用一致性和耗时。未配置密钥时明确退出，不生成假准确率。环境预检结果见 `v2.2-evaluation-status.json`。

真实数据库集成测试使用确定性模型替身，只替代模型决策，SQL安全网关、异步连接池、PostgreSQL、会话快照和答案引用均是真实实现。测试故意让模型输出999999等虚构数字，检查最终响应只包含数据库结果；并验证北京时间月界。可复核演示见 `v2.2-demo.json`。这不是LLM质量评测报告。
